# Mix ears (prototype): live listening, reference comparison, EQ suggestions

Gives the assistant a measuring loop for mixing: **measure → change → measure
again**. A small Max for Live device on the master (and optionally on single
tracks) streams levels and a 1/3-octave spectrum to the MCP server. The server
compares it with a reference track or profile, suggests EQ moves, finds tracks
that mask each other and can write the moves into an EQ Eight as one undo step.

Status: **not tested in Live or Max yet.** Everything below the Max device is
covered by tests with synthetic signals and a faked Live (`tests/test_mix_ears.py`).

## Tools

| Tool | What it does |
|---|---|
| `get_mix_feed_status` | UDP port, which tracks are sending, saved profiles and snapshots |
| `get_mix_analysis(source, seconds, target, snapshot_as, against)` | listens while Live plays: peak/RMS, crest factor, approx. LUFS, balance, approx. correlation, 31-band levels, relative curve, flags; with `target` also deviation + EQ suggestions; snapshots for before/after |
| `compare_to_reference(reference_path \| profile, mix_path?)` | mix (live or file) vs reference file/profile: per-band deviation, loudness of both, EQ suggestions |
| `save_reference_profile(name, path, start_s, end_s)` | stores a reference track's 31-band curve (no audio) as a reusable target |
| `get_masking_report(seconds)` | needs MixEars on several tracks: pairs that compete in the same bands (e.g. kick vs bass at 60–120 Hz) with a carving/sidechain hint |
| `apply_eq_suggestions(track_index, moves, track_type, device_index, dry_run)` | writes moves into an existing EQ Eight via the device registry (one guarded batch, one undo step) |
| `get_mix_spectrogram(source, seconds \| path)` | PNG spectrogram from the live feed (31 rows) or from a file (STFT) |

A typical session:

```text
get_mix_analysis(seconds=8, target="techno-ref", snapshot_as="before")
  -> eq_suggestions: [{type: bell, freq_hz: 250, gain_db: -2.8, q: 0.82, reason: "too much mud ..."}]
load_instrument_or_effect(...EQ Eight on the master...)          # if there is none yet
apply_eq_suggestions(track_type="master", track_index=0, moves=[...], dry_run=true)
apply_eq_suggestions(track_type="master", track_index=0, moves=[...])
get_mix_analysis(seconds=8, target="techno-ref", against="before")   # did it help?
```

## Measuring conventions

* **Bands:** 31 bands, centres `1 kHz · 2^(k/3)` (≈20 Hz … 20 kHz), two-pole
  band-pass resonators with Q 4.318 (1/3 octave), measured on the mid signal.
  Reference files are run through the same filter bank in Python
  (`MCP_Server/ears/thirds.py`), so live and file curves are comparable.
  The digital filters' warping near Nyquist is undone per band
  (`bank_correction`); set `ABLETON_MCP_MIX_SR` if Live runs at 44.1 kHz.
* **Relative curve:** band power ÷ total power in dB. Loudness-independent, so
  a quiet mix and a mastered reference can be compared directly. Deviations are
  re-centred on their median.
* **Targets:** a saved profile name, or `tilt:<slope>` = constant slope in dB
  per octave of band power (pink noise = 0; mixes are typically around −1 to −3).
  Saved profiles are the better target: build them from your own reference tracks.
* **EQ suggestions:** smoothed deviation, tolerance 1.5 dB (wider below 40 Hz
  and above 12.5 kHz), correct ~60 % of it, max ±6 dB, max 4 moves. Bell width
  comes from the width at half the peak deviation. Excess below 50 Hz becomes a
  low cut, edge bands become shelves.
* **Loudness:** `loudness_lufs_approx` is estimated from the L/R levels and the
  K-weighted band spectrum, with BS.1770 gating over 400 ms blocks. In tests it
  lands within 1 LU of a real integrated LUFS measurement; it is not a meter.
* **Correlation:** approximated from mid and side power,
  `(M² − S²) / (M² + S²)`; exact when both channels are equally loud.
* **Masking:** a band is contested when two tracks are above −60 dBFS, within
  12 dB of the loudest track in that band and within 6 dB of each other.

## The Max for Live device

`m4l/MixEars.maxpat` is generated by `m4l/build_mixears_patch.py` (run it
after editing). It sends one OSC message per 50 ms to `127.0.0.1:9881`:

```
/mixears/frame  <track name>  rmsL rmsR peakL peakR rmsMid rmsSide  band0 … band30
```

Audio passes through unchanged. The track name comes from
`live.path this_device canonical_parent` + `live.observer name`, so renaming
the track renames the source. The server only listens on 127.0.0.1;
`ABLETON_MCP_MIX_PORT` changes the port (also change `udpsend` in the device).

### Building the .amxd (once)

1. In Live, drag **Max Audio Effect** (Audio Effects → Max for Live) onto the master track.
2. Click the device's edit button to open the Max editor.
3. In Max: *File → Open…* `m4l/MixEars.maxpat`, select all (Cmd/Ctrl+A), copy.
4. Back in the device editor, delete the default `plugin~`/`plugout~`, paste.
5. *File → Save As…* `MixEars.amxd` (e.g. in your User Library), close the editor.
6. Optional: drop more MixEars instances on tracks you want masking checks for.

### Calibrating (first test)

Play pink noise through the master (e.g. a Simpler with a pink noise sample, or
Operator's noise oscillator), then `get_mix_analysis(target="tilt:0")`: the
relative curve should be flat within about ±1 dB (except below ~30 Hz if your
noise has no deep sub). If the curve is clearly tilted or rippled, the `fffb~`
arguments (count, base frequency, ratio, Q) need a look.

## Without Max for Live

* **Software feed:** `python -m MCP_Server.ears.mixsim mix.wav --source Master`
  plays a file's frames to the server in real time (same maths as the device).
  Useful to try the tools without Live, or to feed stems as several sources.
* **File analysis:** record with `record_audio` (BlackHole loopback) or bounce
  a section, then `compare_to_reference(reference_path=..., mix_path=...)`.
  Upstream's `analyze_audio_file` gives the full offline report.

## Not done yet

* Not tested in Live/Max; the `fffb~` argument order and the name observer are
  from documentation, not from a running device.
* No genre profiles are shipped; build them from reference tracks.
* Suggestions are static EQ only (no dynamic EQ, compression or sidechain setup).
* EQ Eight is not inserted automatically; filter-type names are matched loosely
  (`Bell`, `Low Shelf`, `High Shelf`, `Low Cut … 12`) against the scanned items.
